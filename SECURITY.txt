ОБЩАЯ СХЕМА ЖИЗНЕННОГО ЦИКЛА ДАННЫХ:
--------------------------------------------------------------------------------
[Пользователь в Telegram]
       │
       ▼ (1. Ввод и мгновенное скрытие: await message.delete())
[Оперативная память бота (FSM)]
       │
       ▼ (2. Шифрование Fernet AES-128-CBC + HMAC-SHA256)
[База данных SQLite (users_data.db)] ──▶ В файле хранится только токен (gAAAAABn...)
       │
       ▼ (3. Дешифрование "на лету" строго в RAM на время запроса)
[HTTP-клиент httpx]
       │
       ▼ (4. Защищённый сетевой канал HTTPS / TLS 1.3)
[Официальный студенческий портал университета tou.edu.kz]


================================================================================
1. ДЕТАЛЬНАЯ ЗАЩИТА ЛОГИНА И ПАРОЛЯ
================================================================================

1.1. ЗАЩИТА НА ЭТАПЕ ВВОДА (IN-FLIGHT PROTECTION)
--------------------------------------------------------------------------------
* Проблема: Если студент вводит пароль в чате, сообщение остаётся на экране
  устройства, сохраняется в облачной истории сообщений Telegram и может быть
  прочитано третьими лицами (при физическом доступе к телефону или через плечо).
* Решение в ToU Bot:
  1. Бот переходит в состояние FSM (AuthForm.waiting_for_password).
  2. Как только сообщение с паролем поступает, бот считывает текст в переменную
     в оперативной памяти и НЕМЕДЛЕННО отправляет вызов API:
         await message.delete()
  3. Сообщение удаляется из чата за доли секунды. Пароль не остаётся ни
     в диалоге, ни в push-уведомлениях, ни на серверах Telegram.

1.2. КРИПТОГРАФИЧЕСКОЕ ШИФРОВАНИЕ ПРИ ХРАНЕНИИ (AT-REST ENCRYPTION)
--------------------------------------------------------------------------------
* Проблема: При утечке файла базы данных users_data.db злоумышленник не должен
  получить доступ к паролям пользователей.
* Решение в ToU Bot:
  Для защиты используется криптографический стандарт Fernet из библиотеки
  Python cryptography.
  - Алгоритм: Симметричный блочный шифр AES-128 в режиме сцепления блоков (CBC).
  - Уникальный IV (Initialization Vector): Для каждого шифрования генерируется
    случайный криптографический шум. Даже если два пользователя введут одинаковый
    пароль (например, "student2026"), их зашифрованные токены в базе будут
    абсолютно разными и уникальными.
  - Аутентификация и контроль целостности (HMAC-SHA256): Защита от модификации.
    Если злоумышленник попытается изменить байты в базе, алгоритм мгновенно
    обнаружит подделку и заблокирует расшифровку.
* Пример того, что хранится в базе данных SQLite:
    Реальный пароль:   student_pass_2026!
    В базе данных:     gAAAAABnh_83K1PqX9xLM8z2V7uT9_AbC12e...y9w2E-aB0qWc=
  Даже имея прямой доступ к базе, прочитать пароль невозможно.

1.3. УПРАВЛЕНИЕ СЕКРЕТНЫМ КЛЮЧОМ (KEY MANAGEMENT)
--------------------------------------------------------------------------------
* При первом запуске бота генерируется 256-битный криптостойкий мастер-ключ
  и сохраняется в файл: data/secret.key.
* Меры предосторожности:
  - Файл secret.key строго прописан в .gitignore и никогда не попадает
    в GitHub или публичные репозитории.
  - База данных users_data.db и ключ secret.key логически и физически разделены.
  - Без файла secret.key база данных представляет собой массив нечитаемых байтов.

1.4. ИСПОЛЬЗОВАНИЕ ПАРОЛЯ ТОЛЬКО В ОПЕРАТИВНОЙ ПАМЯТИ (IN-MEMORY ONLY)
--------------------------------------------------------------------------------
* Пароль никогда не пишется в логи, stdout, файлы отладки или кэш.
* Расшифровка происходит "на лету" строго перед отправкой формы входа:
      decrypted_pw = cipher_suite.decrypt(encrypted_pw.encode()).decode()
* Временная переменная существует в памяти доли секунды и уничтожается
  автоматическим сборщиком мусора Python (Garbage Collector) сразу после
  получения ответа от портала.

1.5. ПЕРЕДАЧА ДАННЫХ ПО СЕТИ (IN-TRANSIT SECURITY)
--------------------------------------------------------------------------------
* Все сетевые запросы к порталу Торайгыров Университета осуществляются строго
  на защищённый URL-адрес:
      https://tou.edu.kz/student_cabinet/index.php?lang=rus
* Используется шифрование TLS 1.2 / TLS 1.3 (HTTPS).
* Логины, пароли и сессионные cookies (PHPSESSID) передаются в зашифрованном
  туннеле, что полностью исключает перехват данных (атаки Man-in-the-Middle)
  провайдерами интернета или в публичных сетях Wi-Fi.


================================================================================
2. ЗАЩИТА БАЗЫ ДАННЫХ И СИСТЕМЫ В ЦЕЛОМ
================================================================================

2.1. ПОЛНАЯ ЗАЩИТА ОТ SQL-ИНЪЕКЦИЙ (SQL INJECTION)
--------------------------------------------------------------------------------
* В коде исключена подстановка значений через f-строки или конкатенацию строк.
* Все запросы к SQLite через aiosqlite строго параметризованы:
      await db.execute(
          "SELECT login, password FROM users WHERE user_id = ?",
          (user_id,)
      )
* Любые специальные символы в логине (кавычки, спецзнаки, SQL-команды)
  обрабатываются базой исключительно как обычный текст.

2.2. РАЗГРАНИЧЕНИЕ ПРАВ ДОСТУПА (RBAC) И АДМИН-ПАНЕЛЬ
--------------------------------------------------------------------------------
* Список доверенных администраторов (ADMIN_IDS) хранится в файле .env.
* Все команды администратора (/admin), рассылки и просмотр статистики
  проверяют Telegram ID инициатора на каждом этапе:
      if message.from_user.id not in ADMIN_IDS:
          return
* Обычные пользователи не видят кнопку админ-панели и не могут выполнить
  служебные команды.

2.3. ПРАВО НА ЗАБВЕНИЕ (УДАЛЕНИЕ ДАННЫХ ПОЛЬЗОВАТЕЛЯ)
--------------------------------------------------------------------------------
* Пользователь может в любой момент очистить чат командой /clear.
* Предусмотрена возможность полного удаления связки логина, зашифрованного
  пароля и кэшированных расписаний из базы данных SQLite по запросу.
* Бот не использует внешние аналитические сервисы, рекламные трекеры
  или сторонние облачные базы данных — всё работает автономно.
